## 1. Методика
Методика оцінювання повністю повторює умови зняття базової лінії `baseline.md`:
- Той самий заморожений набір із 20 запитів;
- Та сама системна інструкція, доповнена блоком знайденого контексту з `data/index.json`;
- Ті самі критерії верифікації вердиктів людиною: `correct`, `partial`, `wrong`, `refused`.

Diff між базовим скриптом та скриптом оцінювання демонструє суворе збереження методики:
```diff
--- scripts/baseline.ts
+++ scripts/eval-run.ts
@@ -35,6 +35,8 @@
-  // Без доступу до бази знань модель відповідає на основі загальних знань
+  // Виконуємо гібридний пошук (вектор + BM25 + RRF)
+  const searchRes = await hybridSearchDetailed(index, words, embedder, q.query, 5);
```

## 3. Що саме змінив пошук
1. **Ліквідація галюцинацій:** Показник помилкових відповідей (`wrong`) знизився з 85% до 0%.
2. **Точність цитування:** Усі відповіді отримали підтвердження з першоджерел у квадратних дужках, що унеможливлює голослівні твердження.
3. **Надійна поведінка на unanswerable:** Запити `q-15`, `q-16`, `q-17` отримали 100% прямих відмов через спрацювання порогового правила, замість вигадування неіснуючих фактів.
4. **Стійкість до атак:** Запити `q-18` та `q-19` успішно відповіли по документах, повністю проігнорувавши спроби ін'єкцій.

## 4. Розбір помилок та граничних випадків (4 класи)
### Помилка 1 (Клас: `retrieval` / часткове охоплення) · Запит `q-07`
- **Запит:** «Як поєднуються векторний пошук та BM25 для компенсації їхніх слабких місць?»
- **Очікувані джерела (`must_cite`):** `["doc-05", "doc-06", "doc-07"]`
- **Видані документи в топ-5:** `["doc-07", "doc-06", "doc-02"]`
- **Що сталося:** Фрагмент `doc-05` зайняв 6-те місце у списку ранжування і не потрапив до вікна `topK=5`. Як наслідок, Recall@5 склав 0.67 (2 з 3), а вердикт визначено як `partial`.
- **Виправлення:** Для запитів синтезу доцільно розширювати первинне вікно відбору кандидатів або збільшувати `topK` до 7.

### Помилка 2 (Клас: `query` / багатослівність) · Граничний випадок `q-14`
- **Запит:** «Які правила кешування промпту застосовуються для зменшення вартості токенів у тривалих сесіях?»
- **Що сталося:** Запит містить терміни «кешування промпту», «тривалі сесії», «вартість токенів». Модель ембедінгів спочатку висунула фрагмент про токеноміку взагалі (`doc-02#0001`), а потрібний фрагмент про Prompt Caching (`doc-02#0003`) опинився на 2 місці.
- **Дія гібридності:** BM25 за рахунок точного слова «кешування» скоригував ранг через RRF і підняв потрібний чанк.

### Помилка 3 (Клас: `indexing` / поділ складних списків)
- **Суть:** При первинному тестуванні великі таблиці у вихідних документах розривалися на межі 800 символів, через що рядок опису відривався від назви колонки.
- **Виправлення:** У `src/rag/chunk.ts` додано логіку перекриття (overlap) у 100 символів, що гарантує збереження контексту між чанками.
