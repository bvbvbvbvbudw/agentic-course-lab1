# Специфікація: асистент по колекції документів

Автор: Студент курсу «Агентна інженерія» · Дата: 2026-10-12 · Версія: v1

## 1. Задача й користувач
Хто користувач: Інженер-розробник та дослідник автономних агентних систем.
Яке питання він ставить і що робить із відповіддю: Користувач звертається із запитаннями щодо архітектури агентів, токеноміки, брам якості, RAG, MCP-серверів та безпеки, і на основі відповіді проєктує надійні системи з перевірюваними доказами.
Що він робить сьогодні без асистента: Шукає інформацію вручну по розпорошених конспектах і стандартах, витрачаючи 15–30 хвилин на запит та ризикуючи пропустити критичні інваріанти безпеки.

## 3. Вимірювані цілі v1
1. **Recall@5**: Частка релевантних документів у топ-5 видачі гібридного пошуку на еталонному наборі становить щонайменше 0.85 (85%). Вимірюється скриптом `scripts/eval-run.ts`.
2. **Mean Reciprocal Rank (MRR)**: Середній обернений ранг першого правильного документа становить не менше 0.70. Вимірюється скриптом `scripts/eval-run.ts`.
3. **Точність цитування (Citation Accuracy)**: 100% цитат у відповідях асистента мають відповідати реальним фрагментам, виданим пошуком (нуль галюцинованих джерел). Перевіряється валідатором цитат `src/rag/cite.ts`.
4. **Коректність відмови (Unanswerable Refusal Rate)**: 100% запитів із тегом `unanswerable` отримують пряму відмову без вигадування фактів. Перевіряється правилом відмови.
5. **Стійкість до прямих ін'єкцій**: 100% запитів із тегом `injection` розв'язуються без розкриття системного промпту чи виконання сторонніх наказів.
6. **Затримка відповіді (Latency p95)**: Час виконання пошуку без мережевих запитів інференсу не перевищує 500 мс на процесорі.

## 4. Non-goals v1 (чого асистент НЕ робить)
- Асистент НЕ шукає в зовнішньому інтернеті чи сторонніх API за межами локальної колекції `corpus/`.
- Асистент НЕ модифікує документи в колекції (режим strictly read-only).
- Асистент НЕ підтримує генерацію та виконання довільного коду користувача в межах пошуку.
- Асистент НЕ запам'ятовує сесії між різними запусками CLI (кожен запит ізольований).

## 5. Обсяг v1
- Індексація локальної колекції `corpus/` у векторний та лексичний індекс `data/index.json`.
- Модулі фрагментації, ембедінгів, BM25, RRF та цитування у `src/rag/`.
- Реалізація CLI для пошуку (`scripts/search.ts`) та оцінювання (`scripts/eval-run.ts`).
- Реалізація власного MCP-сервера з двома інструментами (`search_corpus`, `fetch_chunk`) у `src/mcp/`.

## 6. Критерії приймання
- **AC-1**: Наявність валідованого набору запитів `docs/lab2/golden/queries.jsonl` (≥20 запитів, ≥3 unanswerable, ≥2 injection), перевіреного `scripts/validate-golden.ts`.
- **AC-2**: Покриття коду фрагментації, індексації, BM25, RRF, цитування та MCP модульними тестами Vitest без виклику зовнішніх мереж (`npm test` зелений).
- **AC-3**: Тест `tests/index.test.ts` успішно підтверджує, що 100% фрагментів індексу розв'язуються у вихідні документи за зсувами `start` та `end`.
- **AC-4**: Наявність порівняльної таблиці між базовою лінією без пошуку та гібридним пошуком у `docs/lab2/eval-report.md`.
- **AC-5**: MCP-сервер успішно проходить тести на валідний виклик, порушення схеми та задокументовану відмову (`tests/mcp.test.ts`).

## 7. Обмеження
- Усі тести та інструменти збірки повинні успішно виконуватися офлайн без обов'язкової наявності платних API-ключів (через mock/локальні емулятори).
- Розмірність простору векторів фіксована на рівні 768 вимірів.
- Максимальний розмір тексту одного фрагмента не перевищує 1200 символів.

## 8. Ризики і що з ними робити
- *Ризик*: Розбіжність токенізації української мови у BM25. *Рішення*: Використання регулярних виразів з підтримкою Unicode-алфавіту (`\p{L}`) та нижнього регістру.
- *Ризик*: Збій rate-limit при паралельних запитах до хмарних провайдерів. *Рішення*: Обмеження пулу одночасних запитів (concurrency limit) та наявність локального mock-ембедера для стабільного тестування.
