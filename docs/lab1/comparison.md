## Висновки
- **Де кроків було більше і чому:** У власному агентному циклі локально (6 кроків) та у варіанті Chat Completions (5 кроків) знадобилося більше кроків, ніж у спеціалізованого агента Claude Code (4 кроки). Це зумовлено тим, що наш цикл строго розділяє стадію дослідження репозиторію через `list_files` та `read_file`, а фінальний результат генерує окремим повідомленням згідно із zod-схемою. Крім того, менша модель (`qwen2.5-coder:14b`) послідовно читає файли (`src/health.ts`, `tests/health.test.ts`), тоді як більша frontier-модель здатна вилучити контекст за один пакетний запит.
- **Що ваш цикл зробив гірше за агента кодування (і чого він не вміє: запис файлів, запуск тестів):** Власний цикл кроку 08 навмисно обмежений рівнем довіри L1 («підказка/пропозиція»): він не має інструментів запису файлів (`write_file`) і виконання команд (`bash` / `exec`). Він не може самостійно запустити `npm test` або `npm run build`, щоб переконатися у відсутності помилок компіляції чи падінь контрактів; відповідальність за валідацію та застосування diff покладена на людину. Також локальна модель генерує відповідь повільніше (сумарна затримка понад 40-120 с через локальне виконання на GPU/NPU) порівняно з хмарними API.
- **Звідки різниця у вхідних токенах:** Різниця зумовлена багатокроковим контекстом: при кожному наступному кроці агентного циклу повна історія повідомлень (попередні запити, виклики інструментів та їх результати) надсилається повторно. Водночас завдяки роботі механізму Prompt Cache в Ollama (KV cache) понад 85% вхідних токенів у повторних кроках (наприклад, 4301 із 4939 токенів у прогоні #1) читаються з пам'яті, що кардинально скорочує час обчислення префіксу.
