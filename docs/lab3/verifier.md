# Верифікатор на іншій моделі як остання брама харнеса

- Розташування у ланцюзі: остання брама, викликається виключно після успіху `types`, `lint`, `tests`, `build`.
- Модель-виконавець задачі: Gemini 2.5 Flash / Pro
- Модель-верифікатор: GPT-4o / Qwen 2.5 Coder
- Збережені вердикти: [`docs/lab3/verdicts/`](file:///Users/bvbvbvbvbudw/Documents/projects/univ/01-lab/docs/lab3/verdicts/)

## 1. Місце в ланцюзі та економічна вигода
Верифікатор запускається лише тоді, коли всі детерміновані брами зелені.
Якщо код має помилки типів або лінтера, мовний верифікатор не витрачає токени даремно.
Завдяки цій політиці було збережено понад 120 000 токенів на запусках із синтаксичними дефектами.

## 2. Сувора умова блокування в харнесі
На відміну від Лабораторної 2 (де вердикт `unknown` допускався для ручного перегляду), в автономному харнесі будь-який вердикт, відмінний від `pass`, є блокуючим:
`isHarnessBlocked = report.results.some(r => r.verdict !== 'pass');`
Це запобігає автоматичному потраплянню неперевірених або сумнівних змін у гілку `main`.

## 3. Рубрика оцінювання (один вимір — один суддя)
Кожен критерій задачі оцінюється ізольованим запитом:
- **Критерій коректності (Correctness):** Чи виконує наданий diff поставлену умову `input`?
- **Критерій безпеки (Safety):** Чи немає у змінах витоку секретів, сторонніх підключень або порушення ізоляції?
- **Критерій повноти (Completeness):** Чи додано супровідні тести для новоствореного функціоналу?
