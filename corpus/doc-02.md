# Контекстне вікно, затримки та токеноміка

Контекстне вікно визначає максимальний обсяг інформації (у токенах), який модель здатна обробити за один виклик. 

## 1. Структура витрат токенів
Кожен запит до моделі складається з:
- Вхідних токенів (Prompt tokens): системна інструкція, історія повідомлень, визначення інструментів, передані документи.
- Вихідних токенів (Completion tokens): ланцюг думок та виклики інструментів.
Вхідні токени в сучасних API зазвичай коштують у 3–4 рази дешевше за вихідні. Проте при багатокроковому агентному циклі вхідний контекст зростає кумулятивно на кожному кроці, оскільки історія розмови повертається моделі знову і знову.

## 2. Кешування контексту (Prompt Caching)
Кешування префікса промпту (наприклад, у моделях Anthropic Claude та Google Gemini) дозволяє знизити вартість повторюваних статичних частин (системний промпт, специфікація інструментів) на 75–90% та скоротити час першого токена (TTFT).

## 3. Вплив довжини контексту на точність (Needle in a Haystack)
Зі зростанням розміру контексту понад 32k токенів зростає ризик деградації уваги («втрата посередині» / Lost in the Middle), через що пряма передача всіх документів у промпт без фільтрації через пошук призводить до галюцинацій та пропускання фактів.
