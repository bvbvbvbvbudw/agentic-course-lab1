# Протокол Model Context Protocol (MCP) — архітектура та безпека

Model Context Protocol (MCP) — відкритий стандарт зв'язку між клієнтськими застосунками (агентами кодування, середовищами розробки) та серверами контексту, що надають інструменти (Tools), ресурси (Resources) та промпти (Prompts).

## 1. Транспорт stdio та життєвий цикл процесу
Для локальної роботи стандартом є транспорт `stdio`:
- Клієнт (наприклад Claude Code, VSCode або Next.js бекенд) породжує дочірній процес сервера як підпроцес.
- Обмін повідомленнями відбувається за протоколом JSON-RPC 2.0 через стандартні потоки вводу/виводу stdin та stdout.
- Увесь діагностичний вивід та логи сервера спрямовуються виключно в stderr, оскільки будь-який сторонній текст у stdout ламає розбір JSON-RPC повідомлень.

## 2. Чотири стовпи безпеки MCP-сервера
Сервер контексту, що виконується локально, повинен реалізовувати такі інваріанти:
1. Строга валідація вхідних даних схемою Zod (`.strict()`) із обмеженням довжини рядків та діапазону чисел.
2. Явний allowlist дозволених значень (наприклад, доступ лише до заздалегідь проіндексованих ідентифікаторів чанків замість передачі довільних шляхів файлової системи).
3. Примусовий внутрішній таймаут на виконання обробника (наприклад, 10 секунд).
4. Відсутність збережених секретів та API-ключів у конфігурації підключення (використання безпечних змінних оточення хостової системи).
